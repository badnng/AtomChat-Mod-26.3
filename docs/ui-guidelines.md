# AtomChat Miuix UI guide

This guide describes the **active Miuix interface in the 26.3 NeoForge target**. It uses the official Miuix Compose Multiplatform library and its native components. It is not the older Java/Skija approximation that remains in archived source targets.

Use the [official Miuix component docs](https://compose-miuix-ui.github.io/miuix/components/index), especially [NavigationBar](https://compose-miuix-ui.github.io/miuix/components/navigationbar) and [squircle shapes](https://compose-miuix-ui.github.io/miuix/guide/squircle), for upstream APIs. The design note at `D:\nngGram\demo\docs\ui-guidelines.md` is a reference; the current Miuix APIs and AtomChat integration rules in this guide are authoritative for this repository. The local glass reference is `D:\nngGram\demo\shared\src\commonMain\kotlin\com\badnng\moe\ChatGlassUi.kt`; it informs the chat sampling and blur treatment. The implementation source of truth is `ui-miuix/src/main/kotlin/com/atom/chat/miuix/`.

## Style choice and supported target

`AtomChatConfig.UiStyle` is saved in the local client config. `ATOMCHAT` remains the default and keeps the existing interface. `MIUIX` selects the native Compose scene immediately. The choice is independent from color presets and can be changed back at any time.

In the default AtomChat interface, the control is under **Settings → Appearance → Theme tab → Interface style**. In MIUIX, it is under **Settings → Appearance → Interface style**. The MIUIX-only bottom navigation option is alongside it in the AtomChat Theme tab and under MIUIX Appearance. It cycles through `ICON_ONLY`, `ICON_AND_TEXT` (the default), `SELECTED_LABEL`, and `FLOATING`; the first three use Miuix `NavigationBar` display modes, while `FLOATING` uses Miuix `FloatingNavigationBar`. Both presentations share `AppBottomNavigation` and one root-tab model. Standard navigation has a distinct surface and the upstream top divider. The floating capsule fills the width between the outer panel corner arcs, distributes its tabs equally, and uses the upstream outline plus a legible blurred surface. Its own capsule modifier applies `textureBlur` and clears the internal fill so the shaped blur stays visible. The setting is persisted independently and is ignored by the `ATOMCHAT` interface.

`26.3-neoforge` is the active buildable target for this Compose interface. The archived 1.21.1 Fabric and 1.20.1 Forge sources still contain the old Java UI implementation; do not treat those copies as the active Miuix port or add new Miuix behavior to their Skija adapters.

Miuix itself does not bundle a font. Both interfaces share the existing Noto Sans SC variable resource in the outer mod JAR. Compose resolves its regular, medium, bold and heavy faces from those same bytes; classic headings clone the `wght` axis at 700 instead of loading a second static font. Preserve Miuix's stock style weights and rely on system glyph fallback outside the bundled character set. Do not copy the font into the private Miuix runtime or add complete multilingual font packs.

## Module and host boundary

The root target includes `ui-miuix` as a private runtime inside the mod JAR. The module uses Kotlin `2.4.20`, Compose Multiplatform `1.12.1`, Miuix `0.9.4`, and Skiko `0.150.1`; only the matching Windows x64 or Linux x64 Skiko runtime is packaged. Miuix is marked experimental upstream, so keep its version pinned and verify API changes before updating it.

`NativeMiuixRuntime` owns a `CanvasLayersComposeScene` backed by the Compose Multiplatform / Skiko Skia runtime. The active renderer allocates a dedicated color texture, FBO, and stencil attachment inside the current `SharedGlSession`. Compose Skiko draws to that FBO; HumbleUI Skija snapshots the same GPU-backed target when the scene generation changes, then the outer AtomChat renderer composites that retained image each game frame. The bridge does not read pixels back to the CPU on this path. It copies raw pixels only through the compatibility fallback when a shared GL session is unavailable or the GPU path fails. The producer owns each FBO; the consuming Skia binding wraps its numeric OpenGL name as a borrowed render target in the current native GL session. Pass only object names and generation/context metadata across bindings—never Skia objects or binding-owned texture wrappers—and release borrowed wrappers before their `DirectContext` or owning `SharedGlSession` ends. `AtomChatScreen` continues to own the Minecraft screen, panel placement, input callbacks, and game lifecycle.

The Java `MiuixHost` interface is the mapping-neutral boundary. Each frame supplies a snapshot of route, messages, settings, profile, composer, and appearance state. Compose events call back through stable IDs and `MiuixHost.Command`; existing Java services remain the source of truth for persistence, networking, chat actions, and image storage. Do not duplicate that domain state in Kotlin.

## Use Miuix components directly

Build MIUIX pages with upstream Miuix composables from `ui-miuix`. `MiuixApp` uses `Scaffold`, the upstream large-title `TopAppBar`, and Miuix bottom navigation. The page implementations use Miuix cards, preferences, switches, sliders, text fields, icons, and overlay dialogs. The settings root lists the existing settings sections; the section view maps supported setting records to native Miuix preference components.

Keep AtomChat-owned content and actions in the host snapshot. The user-approved stock Miuix screenshot is the visual baseline for chrome, preferences and navigation: retain upstream Miuix typography, semantic colors, component shapes and icons, overriding only the primary accent. The user explicitly chose the original AtomChat layout for chat bubbles, message typography and avatars. Read those design metrics and message colors from the host; do not apply the chat-specific layout to other Miuix components.

The Miuix avatar uses the same Java-side poke timestamp and follows the global animation setting. Preserve that host signal instead of adding an independent poke state in Compose.

`MiuixApp` starts from Miuix's stock light or dark scheme, selected from the configured panel color, and overrides only Miuix `primary` with AtomChat's accent. Existing AtomChat chat-bubble fills and text colors remain in use; the component palette stays stock Miuix. Panel opacity, wallpaper, blur, dimensions, and scale are passed through where the host and renderer use them. The native Appearance section's `Miuix theme` choice selects the light or dark stock scheme by updating the panel color that seeds that choice. Hide legacy card tint/color, outline, primary/secondary text, and capsule color controls from native preferences; retain their stored values for the AtomChat style.

Use upstream Miuix shapes and modifiers for Miuix components. `MiuixApp` applies the configured `cornerRadius` with Miuix's `squircleClip` to the outer panel window, and each secondary-page container carries the same clip with its own push/pop transform. This prevents translated pages exposing rectangular corners inside the fixed panel. Individual controls retain their Miuix radii; root-tab fades retain their shared shell. Do not route active MIUIX rendering through the legacy `DrawPrimitives`, `UiCards`, `ToggleSwitch`, `MiuixComponents`, or `UiSurfaces` Skija path.

## Follow the approved Miuix visual baseline

Use the single shared `ChatTopAppBar` wrapper with upstream Miuix title rendering; do not hide a library title and overlay a second copy. Standard pages connect the large-title `TopAppBar` and scrolling page to the same `MiuixScrollBehavior`. Chats use a pinned `SmallTopAppBar` and leave transcript scrolling disconnected from bar collapse, so incoming-message following and history scrolling cannot move the header. The shared 20 dp safe area centers local `HH:mm` time across the panel width, using 16 sp medium text, tabular digits and the stock secondary text color; it updates only at minute boundaries. The About page uses the same compact bar with its title always visible. The top-right Close button is omitted, matching AtomChat; preserve Back, the world-chat filter and keyboard closing.

Chat rows follow the original AtomChat `MessageListView` geometry through host `UiMetrics`: both sides show an avatar and a name band above the bubble on the first row of a group, with own messages mirrored to the right. Grouped rows omit repeated identity content. Use the original body/name/quote font sizes and natural font line metrics, avatar size and gap, bubble padding, radius and wrapping budget. Text bubbles hug their content instead of using a fixed 320 dp width. Preserve configured bubble colors, rich text, selection, timestamps, image previews, reactions and the existing message menu. System messages use the original smaller centered capsule treatment.

The persistent More button below each bubble is removed. A circular Copy button appears near the final visible glyph's lower-right corner while the pointer is nearby, then fades away; it also has a keyboard-focus path. Derive its anchor from the actual text layout, respecting emoji clusters, trailing empty lines and bidirectional text. Reserve its footprint outside the filled bubble so hover cannot move text or cover a neighboring message, and disable pointer handling while hidden. A message right-click opens the original compact vertical Copy/Reply/React menu with icons; image messages also expose Save. Anchor it to the actual bubble and clamp it within the transcript, rather than positioning it at the mouse cursor. Opening and closing fade and scale; reactions are a separate lazily composed picker reached only through React, with Escape returning to the basic menu first. Keep avatar/profile/whisper actions in their existing identity paths rather than crowding the bubble menu. Completion and other composer popups retain Escape priority.

Keep the composer aligned with that reference: the text field occupies the left side of the top row and Send sits on its right. The row underneath contains three tools in order: emoji, phrase, image. Stickers remain available through the emoji popup's Stickers tab; do not add a separate sticker toolbar button.

The emoji popup aligns to the measured composer bounds and opens above them with the same width. Use the upstream `TabRowWithContour` and pager from Miuix's “Content of Tab” example for Emoji, Kaomoji and Stickers, with animated selection and page movement respecting the global animation setting. Reuse the original kaomoji catalog through the host. Use stable-key lazy grids with evenly spaced square emoji targets and subtle pointer feedback instead of permanently filled pills. The sticker-add slot is a square plus icon with visible hover feedback. Loaded static thumbnails stop polling, and a file revision in the opaque sticker key refreshes overwritten files. The host reuses sticker rows between directory scans instead of rebuilding them every frame. Keep the existing phrase editor, permissions and focus restoration.

New message bubbles fade in and rise 16 dp over 260 ms only when appended while the user is following the conversation. Track each arrival once per conversation/filter baseline; opening history, loading older messages, jumping, and scrolling back do not replay it. Drive this with Compose animation state rather than lazy-item appearance alone: the follow operation's `scrollToItem` resets Compose's lazy item animator.

Keyword effects share AtomChat's existing matcher, session and renderer. Native redraw checks must use `ChatEffectPresentation.nowMs()`, the same monotonic clock as triggering and drawing; passing wall-clock milliseconds expires the burst before it can render. Keep the existing fun-effects/global-animation settings and current-conversation, fresh-message filtering.

Notification cards use the Scaffold popup layer above its bars, preserving the upstream popup host above the cards. Retain the Scaffold's actual top and bottom padding so banners stay below the header and above the composer; the header's extra 16 dp feather must not cover their corners. The stack uses the available viewport instead of a fixed 240 dp crop. Animate new cards within their own bounds, move the existing stack with lazy-item placement, and fade removed cards out. The Java queue still owns ordering, expiry and actions, and all presentation motion follows the global animation setting.

Keep the shared input semantics too. Avatar clicks use AtomChat's existing 300 ms arbitration so one click can open a profile while a second click in that window sends the configured poke and cancels the pending profile action. A message right-click opens the Miuix context menu with the existing message actions. Preserve the accessible action path and the current Java-side action commands when modifying those controls. Keep Miuix's Send and Close icons and the original AtomChat vectors for the chat filter, Emoji, and QuickPhrase. The filter retains the original `ALL → SYSTEM → PLAYERS` cycle, switching between Filter, Announcement, and Player glyphs with the corresponding tint and a glyph fade.

The About route follows AtomChat's original `SettingsSectionPage` layout and bundled assets. Its scrolling brand row contains the app icon, the flat red `logo_wordmark.png` artwork and the real loader version badge, without a hero card. Below it, the two author cards show the original E33EPUS and NoWordz images and names. Mod information (version, license and repository), third-party components and advanced actions each share one card with row dividers; their headings can collapse the groups and start expanded. Keep version links, external links, debug settings and cache-clear confirmation connected to the existing host actions. Build this layout with the same Miuix cards and preferences as the rest of the native interface. The OS3 dynamic background remains an upstream effect adaptation, reusing its shader and presets without additional dependencies or images. Animate only while the brand row is visible and global animations are enabled, cap updates at 60 Hz, and release the mounted shader builder on disposal.

Root tabs share one `Scaffold`, keeping the native bottom-navigation selection indicator mounted. Only root page content crossfades over 160 ms; `miuix-root-tabs-running` marks that transition. The existing `pageNavStyle` setting (`SLIDE` or `ZOOM`) controls secondary-page push/pop only. `SLIDE` uses 500 ms horizontal motion with quarter-width parallax on the covered page. `ZOOM` is serial: the outgoing page shrinks to 90% and fades out over 180 ms, then the incoming page starts after a 180 ms delay and scales from 110% while fading in over 260 ms. The global animation setting disables these transitions through Compose's motion scale. While a transition runs, the outgoing page keeps its own route snapshot; pointer and key input are consumed, and command, draft-text, focus, and clipboard callbacks are accepted only from the active page.

The profile preserves AtomChat's banner, overlapping avatar, signature, ping/session/mined statistics, and role/server/UUID information, presented with actual Miuix cards. Signatures edit inline below the name, with the original 256-character limit, Enter/IME Done to save and Escape to cancel. Clear focus before navigating or closing so pending profile edits commit while their page host remains active. Keep own-profile and other-player restrictions and the existing backend actions; changing the presentation must not grant editing or player actions that the host does not expose.

Desktop lists attached to a collapsible header share `DesktopPageFlingBehavior`. It returns unused wheel velocity to the parent bar without adding a second inertial scroll. Compose's default desktop wheel behavior omits the parent's end-of-scroll notification; after reaching the list boundary that can strand a tall title partway through expansion. Keep this policy shared by Conversations, Settings and Profile, and leave pinned chat and About lists independent from header collapse.

## Glass and blur pipeline

The Minecraft panel reserves a fixed 20 dp top safe area inside its blurred app bar, containing the centered 16 sp local clock. It applies in expanded and collapsed states, keeping Back/Close actions away from the rounded panel edge; it is local panel spacing rather than an Android status-bar inset.

The classic renderer captures only the physical panel animation envelope plus a 32 px Gaussian guard, using one reusable asynchronous readback. Quarter-size 4×4 averaging, blur filter, paint, pixel storage and raster are retained across samples; unchanged source pixels keep the previous blurred image. This preserves the original blur strength without the full-world Screenshot CPU downscale path. Fully open classic emoji panels draw directly, using an alpha layer only during open/close animation.

`PanelBlurRenderer.captureWorld()` supplies unblurred game-world pixels after world rendering and before Minecraft composes the GUI. All background-capture paths use one shared 60 Hz cadence, independent of camera motion and game FPS. The classic AtomChat path keeps its downsampled Gaussian treatment but no longer skips alternate frames or slows still scenes to 500 ms. MIUIX OpenGL refreshes its full-resolution world FBO at every due slot without a motion-probe gate. On Vulkan, MIUIX reads only the panel region through one reusable staging buffer, with at most one asynchronous readback in flight and a 60 Hz target cadence. Capture remains bounded by rendered frames and asynchronous completion; it is not a guarantee of 60 displayed frames on a slower client. Both paths give Compose an unblurred crop of the world; neither feeds an already blurred image.

`MiuixApp` maintains separate world and page `LayerBackdrop`s. `WorldSource` is a sibling of the consumers that sample the game world; the scrolling page source is separate from its top and bottom bars. Keep each capture source outside its own blur consumers so the backdrop never samples itself.

`mixedChatGlass` uses Miuix `textureBlur` over the sampled world, blending the result with Miuix's stock surface at 55% opacity, then applying `Screen` at 20% and `Overlay` at 18%; the configured panel opacity scales these page layers. The top-bar reference is `D:\Hypernotesuper\app\src\main\java\com\Badnng\moe\ui\miuix\MiuixPageUtils.kt`. `TopChatGlass` uses upstream `progressiveTextureBlur`, with `startFraction = 0.15`, `endFraction = 1.0`, `curve = 1.25`, no noise, and a radius limited to 18 dp or 52 physical pixels, whichever is smaller. With collapse progress `c`, its tint blends stock surface at `0.52 * (1 - c)` and a `Multiply` dim layer at `0.14 * c`. Pinned chat bars instead keep a stable 88% stock-surface tint and omit the collapse Multiply layer so scrolling message glyphs cannot interfere with the title. About progressively blurs its own page backdrop from the first screen, including the OS3 artwork and content scrolling beneath the bar. Until the brand row has fully scrolled away, only the surface tint is transparent; that gate must not disable progressive blur. Its title remains visible throughout, and the solid fallback remains absent while the tint is hidden. Do not add saturation 1.1 or scale these top-bar layers by panel opacity. The effect draws a 16 dp feather beyond the bar without adding layout or hit-test height. The composer keeps its approved bottom progressive blur treatment. These gradients vary blur strength and retain the full-resolution clear end. If the runtime shader is unavailable, the page backdrop uses its solid stock-surface fallback and the top-bar/composer blur modifier is omitted. When a wallpaper is active, draw that image using the configured opacity instead of capturing it as game-world input.

Keep the game's AtomChat panel-open transform outside the Compose scene. The bridge crops the world frame to the transformed panel and draws the retained Compose image into the same panel bounds, so the scene and its backdrop move together without capturing the composited panel.

## Render lifecycle, input, and window geometry

The Compose scene and shared GL resources are render-thread-owned. Call `render`, pointer, keyboard, text, and clipboard APIs through `NativeMiuixBridge` on the client/render thread. `SharedGlSession` ties the FBO attachments to the active parent GL context lifetime; close the Compose GPU context, wrapped surfaces, snapshots, and target through that session's lifecycle before the parent context ends. On real session teardown, run cleanup with the old GL context current: cancel uncommitted IME composition, save the in-memory `SaveableStateRegistry`, close the Compose scene and its graphics-layer owners, then release imported GPU images, borrowed surfaces, and the Skiko `DirectContext`. Recreating the scene restores saveable state such as scroll position from that in-memory registry; the Java host remains the source of route/navigation and chat-draft state. A size-only target replacement within the same session retains the scene and `DirectContext`; a new renderer session disposes transient Compose overlays as its scene is rebuilt. Compose advances from `prepareFrame`; the GPU target is redrawn when the scene has pending changes, and a HumbleUI snapshot is refreshed only when the returned scene generation changes. The retained GPU image is still composited into the outer frame on each render call. Keep raw-pixel copying confined to the compatibility fallback.

The existing `animationEnabled` setting feeds Compose `MotionDurationScale` (`1` when enabled, `0` when disabled). Preserve that connection for Miuix animations; do not add a second timer or animation driver. Keep image polling and decode work tied to mounted image nodes, with native images released through their Compose disposal effects.

Native width, interface-scale and content-scale sliders move continuously and preview their thumb and numeric value locally while pressed, then apply and persist the geometry once the gesture ends. The interface-scale slider displays upstream key-point dots at 0.75, 1.00, 1.25 and 1.50; these are visual landmarks with magnetic snapping disabled. Observe the press in the Initial pointer pass and the release in the Final pass; Miuix's Finished callback also runs on cancellation and does not prove that the mouse button was released. Updating the owning viewport or Compose density during that drag can cancel the gesture and repeatedly replace its render target. Other appearance sliders retain live host previews. Cancel native pointer input on window focus loss from both rendering and the client tick so minimizing the window cannot leave a slider captured when rendering stops.

The floating bottom bar follows Hypernotesuper's standard Miuix example: its page backdrop is already mixed with the world or wallpaper, so use 25 dp texture blur, a 60% surface-container tint and the official light/dark GlassStrokeMiddle highlight. Keep the inner bar transparent while blurred and disable its ordinary divider so the glass edge is not drawn twice.

Client setup preloads the existing bundled variable font through the same font-family resolver used by the real scene, then composes and measures a disposable chat and conversation-list scene against a no-op host. Do this once regardless of the saved style so switching to MIUIX after joining also benefits. The temporary scene is created, advanced and closed on the same setup thread before setup returns; it does not allocate a rendering surface or GPU context, access game services, or transfer state to the visible scene. Optional preload failures are logged without stopping client setup. Real scenes and GL targets retain their render-thread and SharedGlSession lifetimes.

Serialize native back/close intent with the host's latest acknowledged page transition. Coalesce rapid Escape during chat entry into one back, and prevent repeated or held Escape from closing the whole panel while that back is in flight. Drain deferred intent on a later host snapshot, not inside the transition acknowledgement callback. A fresh Escape on the settled root can close, and an explicit Close remains queued with priority. Preserve IME and popup consumption first, track held Escape across composition cancellation, and clear only the physical key hold on focus loss from a non-rendering tick path.

Minecraft supplies the window and outer panel geometry. `MiuixApp` uses zero Compose window insets and disables default bar inset padding; do not add Android status-bar, navigation-bar, or display-cutout padding. Mouse, keyboard, and window-focus events enter through the host bridge. Compose text fields synchronize with the hidden Minecraft edit field, and focused rectangles update Minecraft's text-input anchor. `AtomChatScreen.preeditUpdated` forwards Minecraft/SDL preedit text and caret positions into Compose; when Minecraft commits text and clears preedit, clear the Compose composition first so the text is not duplicated. There is no separate OS-owned Compose window or Android haptics path.

During active IME preedit, candidate-selection keys belong to the OS input method: do not send Enter to chat, navigate history with arrows, close on Escape, or run clipboard shortcuts. Update the hidden field's focus only on state changes, and allow its explicit blur while stopping the native text session. Updating the candidate-window anchor must not repeatedly resubmit vanilla preedit. Validate same-batch `KeyboardHandler.textInput` clear-and-commit behavior, supplementary Unicode characters, and SDL activation across leaving and refocusing the composer.

## Verification workflow

Run these from `platforms/26.3-neoforge`:

```powershell
.\gradlew.bat :ui-miuix:test
.\gradlew.bat build
.\gradlew.bat runClient
```

Verify both `ATOMCHAT` and `MIUIX`, all four Miuix navigation modes, the top/bottom progressive blur and its shader fallback, wallpaper opacity, mouse and keyboard actions, IME editing, dialogs, images, notification overlays, and the game panel open/close animation.
